## Phase 检查

读取 `.novel/state.json`。若不存在，停止：`✗ 请先运行 /novel-init`

**前置检查：**
`dev-edit.status` 必须是 `done`，否则停止：
`✗ BLOCKED：请先完成 Phase 2 发展性编辑（/novel-dev-edit）`

## 参数处理

**若参数为 `--mark-done`：**
更新 state.json：`line-edit.status = "done"`，`line-edit.completed_at = <今天>`
输出：`● 行文编辑第 <iteration> 轮标记完成。运行 /novel-copy-edit 进入文字校稿。`
停止。

**若参数为章节文件名（如 `ch01.md`）：**
只分析该章节。

**若参数为 `--all` 或无参数：**
分析所有章节。

将 `line-edit.status` 更新为 `in_progress`，`iteration` +1。

## 执行

读取目标章节文件。

从以下六个维度逐段分析，每条建议必须引用原文，给出具体修改方向（不替你改，只指出问题和方向）：

### 1. 句子节奏
- 连续多个相同句式/句长 → 提示换节奏
- 过长句子导致气口丢失 → 标出断句位置
- 过短句子堆砌导致节奏破碎 → 建议合并

### 2. 语气与声音
- 叙事声音是否一致？有无突然切换人称视角或叙事距离？
- 有无"译文腔"（像从外文翻译过来的中文）？给出具体例子
- 有无说教感（作者直接告诉读者该怎么理解）？

### 3. 对白
- 对白是否有人物辨识度？不同人说话是否听起来不一样？
- 有无"传声筒式对白"（人物只在推进信息，没有性格）？
- 对白节奏：有无过长的独白需要打断？有无对白结束后的动作/心理描写缺失？

### 4. 意象与比喻
- 有无陈腐比喻（"如刀的目光"、"心如刀割"等）？列出并建议方向
- 有无混乱比喻（一个意象前后不一致）？
- 有无特别出彩的意象值得在其他地方呼应？

### 5. 冗余与重复
- 同一信息说了两遍（一次叙述、一次对白又重复）
- 形容词堆叠（两个以上形容词修饰同一个名词）
- 副词滥用（"非常"、"十分"、"极其"）

### 6. 朗读节奏（音律）
- 标出读起来会卡壳的句子（通常是字音相近、韵脚重复、或节奏反直觉）
- 标出特别适合出声读的句子（作为范本）

```
<今天日期>

→ 问题：...
→ 建议方向：...

── 语气 ──────────────────────────────
...

── 对白 ──────────────────────────────
...

── 意象 ──────────────────────────────
...

── 冗余 ──────────────────────────────
...

── 音律 ──────────────────────────────
...

本章共发现 N 处问题（节奏 N，语气 N，对白 N，意象 N，冗余 N，音律 N）
```

**不要改动任何正文文件。只输出问题和方向。**

本轮修改完成后：
- 继续打磨下一轮：`/novel-line-edit`（iteration 会自动递增）
- 确认完成：`/novel-line-edit --mark-done`
