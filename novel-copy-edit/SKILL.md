## Phase 检查

读取 `.novel/state.json`。若不存在，停止：`✗ 请先运行 /novel-init`

**前置检查：**
`line-edit.status` 必须是 `done`，否则停止：
`✗ BLOCKED：请先完成 Phase 3 行文编辑（/novel-line-edit --mark-done）`

**若 `copy-edit.status` 已是 `done`：**
显示完成时间，提示若需重新运行加 `--rerun`，否则停止。

## 参数处理

**若参数为 `--mark-done`：**
更新 state.json：`copy-edit.status = "done"`，`copy-edit.completed_at = <今天>`
输出：`● 文字校稿标记完成。运行 /novel-proofread 进入终校。`
停止。

## 执行（无参数或含 --rerun）

将 `copy-edit.status` 更新为 `in_progress`。

读取 `chapters/` 下所有 `.md` 文件，构建全稿检查清单。

### 1. 人名一致性
扫描全稿中所有人名出现次数。列出同一人物是否有不同写法（如"青辉"/"青晖"，外国人名译法不统一等）。

### 2. 地名与专有名词
列出所有地名、机构名、设备名、专业术语，标出有无前后不一致。

### 3. 时间线核查
整理全稿中所有明确或暗示的时间节点，检查是否有逻辑矛盾（如第3章说事件发生在冬天，第7章又说同一事件时窗外是夏天）。

### 4. 视角一致性
标出全稿中叙事视角（第一/第三人称、远/近距离）的切换点，判断是否为有意为之，还是笔误。

### 5. 标点与格式
- 引号使用是否一致（「」或""，全稿只用一种）
- 省略号是否统一（……而不是...或。。。）
- 破折号是否统一（——而不是—或-）
- 段落首行缩进是否一致

### 6. 语法与搭配
- 主谓宾明显不搭的句子
- 悬空修饰（"作为一名宇航员，飞船轰鸣着起飞"）
- 代词指代不清（"他看着他，他说"——哪个他？）

```
【人名一致性】
✓ 无问题  /  ✗ 发现问题：

【专有名词】
...

【时间线】
...

【视角】
...

【标点格式】
...

【语法搭配】
行 N：[原文] → 问题：...

```

**不要改动任何正文文件。只输出问题清单。**

完成修改后运行：`/novel-copy-edit --mark-done`
