## Phase 检查

读取 `.novel/state.json`。若不存在，停止：`✗ 请先运行 /novel-init`

**前置检查：**
`cold-read.status` 必须是 `done`，否则停止：
`✗ BLOCKED：请先完成 Phase 1 冷读评估（/novel-cold-read）`

**若 `dev-edit.status` 已是 `done`：**
显示完成时间，提示若需重新分析加 `--rerun`，否则停止。

## 参数处理

**若参数为 `--mark-done`：**
更新 state.json：`dev-edit.status = "done"`，`dev-edit.completed_at = <今天>`，`last_major_change = <今天>`
输出：`● 发展性编辑标记完成。运行 /novel-line-edit 进入行文编辑。`
停止。

## 执行（无参数或含 --rerun）

将 `dev-edit.status` 更新为 `in_progress`。

读取 `chapters/` 下所有 `.md` 文件。若 `.novel/` 下存在冷读评估输出文件，也一并读取作为参考。

从以下五个维度做深度分析，每个问题必须标注具体位置（第 N 章，段落引用）：

### 1. 情节逻辑
- 有无因果链断裂？（A 发生了，但没有合理导致 B）
- 有无信息矛盾？（第 X 章说了 Y，第 Z 章又说了相反的）
- 有无悬而未决的线索？（提到了但没有交代）

### 2. 人物动机
- 每个主要人物的核心动机是什么？在全稿中是否一致？
- 哪些行为在情感逻辑上站不住脚？（人物"为了剧情需要"而行动，不是"因为他/她就是这样的人"）
- 人物弧光：从哪里开始，到哪里结束，转变的触发点是什么？是否可信？

### 3. 结构节奏
- 全稿节奏是否均衡？有无过长的平台期（张力持续下沉超过 N 章）？
- 高潮位置是否正确？（通常在全稿 70-80% 处）
- 开头是否足够快速建立世界与人物？结尾是否给了足够的余韵？

### 4. 信息释放
- 关键信息（背景、设定、真相）的释放节奏是否合理？
- 有无过早剧透（读者知道得比人物早太多，失去悬念）？
- 有无信息堆砌（某章突然塞入大量解释性内容）？

### 5. 主题一致性
- 全稿的核心主题是什么？各章节是否在强化还是消解这个主题？
- 有无与主题无关、可以删除的场景或人物？
